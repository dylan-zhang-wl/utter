# Utter

macOS 上的本地优先语音工具，为**口述论证**而不是口述命令的人做的。

两个模式。**说**已经完成、每天在用：按住一个键讲话，文字出现在光标处，落进你本来
就在编辑的那个窗口。**听**还没做：英语讲座或会议的实时转录 + 译中 + 存成文档。

## 为什么又做一个听写工具

同类里已经有好的了。这个存在，是因为一条别人没有认真对待的约束：

> **落进你文档里的字，必须是你说过的字。**

所有带「AI 润色」的听写工具都是把转录发给大模型、然后采用它的返回。本项目实测：
在**明令禁止改写**的提示词下，GPT 和 Gemini 都删掉过学术论证里的「因为」——
一个因果连接词 —— 也都调整过词序。而两个输出都读着非常通顺。

**这正是危险所在**：一个通顺但已经不是你论断的句子，重读一遍抓不出来，
而那时音频已经没了。

所以 Utter 的润色**改不动你的字**。不是"被要求不要改"，是**改不了**：
模型的输出会按内容字符和转录对齐，**只有标点被采纳**，每一个字都来自你说的话。
模型删了词，词自动回来；模型换了词序，词序自动复原；模型凭空造了句子，
那句话根本进不来。

这条性质是这个项目的意义所在。其余都是工程。

## 说 —— 它做什么

- **按住说话**：按住键、讲、松开。整段转录后粘贴到光标处。
- **边说边出字**（默认关闭）：双击键然后一直说。silero VAD 按**你自己的停顿**切句，
  每个小句在你还在说下一句的时候就已经转录并注入了 —— 大约每四秒出一句，
  最后一句在你停下后约一秒落地。
- **标点来自你的停顿。** Whisper 不会给两秒的碎片打标点，所以流式的小句
  由你真实留下的静音来收尾：**换气是逗号，长停顿是句号**。这是量出来的，不是猜的。
- **术语表**在识别阶段生效，让「foreignisation」不会变成「Thorinization」。
  这是**唯一**被允许纠正听错词的一层 —— 因为只有它手上还有音频。
- **绝不静默丢字。** 每句后的耗时报告会说：你按住了多久、录到多少音频、
  其中多少是说话、文字去了哪里。对不上就直接说出来。

### 刻意不做的

- **音频永不落盘。** 只在内存活几秒，转完即弃。这也是存档极小的原因：
  每段 227 字节，而存音频的同类工具同样用量一年是几十 GB。
- **注入过的文字永不回改。** 没有"先出草稿再修正"。文档是你的，
  一个在你背后改字的工具比一个慢的工具更糟。
- **麦克风不常开。** 按热键才开，用完就关。

## 模型

语音识别在本地跑。模型首次使用时下载，不打包进 app —— app 只有几兆，权重是几百兆。

| 引擎 | 中文 | 英文术语 | 中英混说 | 速度 |
|---|---|---|---|---|
| **Whisper large-v3-turbo (MLX)** | 好 | **准** | **两种都保留** | 每秒音频 90–146ms |
| SenseVoice int8 | 好，标点更密 | 差 | **会吞掉英文** | 14–20ms |
| Whisper (CTranslate2) | 好 | 准 | 两种都保留 | CPU —— 给 Windows 和 Intel Mac |

默认 Whisper turbo。SenseVoice 在纯中文下快 4–12 倍、标点更好，
但在含英文术语的中文句子里，它不是听错英文，**是把英文删掉，而且是静默的** ——
对一个中英混说的学者，这一条单独就否掉它作默认。它仍然可选，菜单名里写着代价。

润色是可选的，可走任何 OpenAI 兼容端点、Google Vertex AI（用云凭据，不需要 API key），
或本地 Ollama。**密钥只进 macOS 钥匙串，不落任何文件。**

## 安装

macOS 13+，Apple Silicon 或 Intel。Python 3.11。

```bash
uv venv ~/.venvs/utter
uv pip install --python ~/.venvs/utter/bin/python \
    --overrides requirements-overrides.txt -r requirements.txt
uv pip install --python ~/.venvs/utter/bin/python --no-deps -e .
```

`--overrides` **不是可选的**：`mlx-whisper` 谎报依赖 torch，不加这个参数会拖进 476MB。

然后构建 app：

```bash
# 只需一次 —— 固定签名证书，让 macOS 权限不因重建而丢失
~/.venvs/utter/bin/python packaging/build_app.py --make-cert

~/.venvs/utter/bin/python packaging/build_app.py --login-item
open /Applications/Utter.app
```

macOS 会要**辅助功能**（热键与粘贴）和**麦克风**两个权限。没有辅助功能，
热键收不到任何按键**且不报错**；没有麦克风，macOS 给你静音而不是错误。
两个都有检查，缺哪个会直接说。

也有命令行，调试更方便：

```bash
utter doctor            # 这台机器什么能用、什么不能
utter dictate --timing  # 带逐阶段耗时报告的听写
utter mics              # 真的打开每个输入设备，看哪个收得到声音
utter polish '文字'      # 拿你的真实模型验证润色提示词
```

## 这个项目给自己定的规矩

十三条，在 [CLAUDE.md](CLAUDE.md) 里，每一条都是出过事之后才写下的。塑造架构的那几条：

- 音频永不落盘。
- 注入过的文字永不回改。
- 润色只能补标点、删口水词、分段 —— 不得改写措辞、不得增删内容。
  原始转录必须与润色版一起存档。
- API key 只进钥匙串。
- 任何地方都不引入 torch。
- 绝不静默丢失。

## 教训

[docs/教训与经验.md](docs/教训与经验.md) 记了三十五条，多数与直觉相反，好几条代价不小：

- **Whisper 会在静音里编句子** —— 两秒空房间产出了 `"you"` 和 `"Good job."`；
  中文版的幻觉是片尾字幕的「字幕志愿者」。
- **temperature 阶梯要有界，但不能取消** —— 那条阶梯的用途正是逃出复读循环，
  标量意味着模型无处可退。
- **PortAudio 只在启动时枚举一次设备** —— 常驻进程在你插上耳机后会安静地录到静音。
- **macOS 拒绝麦克风时返回的是「恰好为 0」，不是错误。** 安静房间的真麦克风约 0.001。
  **一列完美的零永远不是测量值，是某个软件里的 `if`。**
- **`.app` 的启动器如果 `exec` 走了**，LaunchServices 永远收不到「启动完成」，
  菜单栏图标也永远不会被布局。
- **权限跟着代码签名走**，所以包装式 app 必须运行 bundle 内部的解释器。

如果你也在 macOS 上折腾 Whisper，这份文件能替你省下好几天 —— 它花掉了我们的。
