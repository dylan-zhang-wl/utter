## 三次无声丢失（已修）

115 − 105 − 7 = 3。这 3 次按键**没有出字，也没有任何一行日志**。

原因是 `end_utterance()` 里：

```python
chunks = list(mic.chunks())
if chunks:
    self._enqueue(...)
# ← 没有 else
```

麦克风一帧都没给出来时，这次按键就凭空消失了。下游"没听到声音"那条路
报得很细（设备、时长、峰值），唯独这条分支什么都不说。
麦克风冷启动实测到过 713ms，所以**按得够短就会命中**。

已加 `else` 分支：报设备、按住了多久、麦克风有没有开起来，并在浮窗上显示。

## 三次"超时"警告其实不是慢

| | 音频 | 处理 | 每秒音频 |
|---|---|---|---|
| 第 2 次 | 16.9s | 10.2s | 606ms |
| 第 21 次 | 49.7s | 10.8s | 216ms |
| 第 101 次 | 68.8s | 16.7s | 243ms |

预算是 `150ms × 音频秒数`，**只按音频长度算，没有算润色那次网络往返**。
长口述里润色的固定开销被摊薄不掉，于是长句必然报警。
后两次的 216 / 243ms 都在正常范围，属于**预算模型该改，不是程序变慢**。
只有 3 个数据点，暂不调阈值。
