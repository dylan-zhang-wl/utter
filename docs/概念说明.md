# Utter 概念说明：这个项目里的术语都是什么意思

写给项目作者本人。不假设软件工程背景，但也不稀释——每个词都落到 Utter 里的具体位置。

---

## 一、前端 / 后端：为什么要分成两半

**后端（backend）** 是干活的那一半：收音、把音频变成文字、翻译或润色、存档。看不见，没有界面。Utter 的后端是 Python。

**前端（frontend）** 是你看得见、点得到的那一半：窗口、按钮、滚动的字幕。Utter 的前端是 Tauri + React。

**为什么不写成一个程序？** 因为两半的最优工具不是同一套。语音识别的库（Whisper 及其各种运行时）几乎都长在 Python 生态里；而做一个好看、好改的桌面界面，用网页技术（HTML/CSS/JS）最省力。硬要统一，就得在某一边将就。

**代价是它们得互相通话。** 这就引出两个词：

- **WebSocket** —— 两个程序之间的一条"电话专线"。区别于普通网页请求（问一句答一句），WebSocket 是**接通后一直开着**，任何一边随时可以说话。Utter 需要它，是因为后端要不停地把新转录的句子推给前端，而不是等前端来问。v1 用的地址是 `ws://127.0.0.1:8765/ws`——`127.0.0.1` 是"本机"，意味着这条线不出你的电脑。

- **sidecar（挎斗）** —— 让主程序启动时顺带把后端也拉起来的机制，名字来自摩托车挎斗。**v1 这条链断了**，所以每次用都得手动开两个终端窗口——评估认为这很可能就是它建好后一次都没被用起来的直接原因。P4 要修的就是这个。

## 二、架构：跟着一句话走一遍

"架构（architecture）"听起来玄，其实就是：**系统由哪些部件组成、数据按什么顺序流过它们。** 跟着一句话走一遍就全清楚了。

假设讲者说了一句 "Translation is a form of rewriting."

| 步骤 | 部件 | 干了什么 |
|---|---|---|
| 1 | **音频采集** `audio_capture` | 麦克风每 100 毫秒交一小包数据，像流水线上的传送带 |
| 2 | **VAD** | 判断"现在有人在说话吗"。检测到静音持续 600 毫秒，就在这里切一刀 |
| 3 | —— | 切出来的这一段，叫一个 **utterance（话语）**。项目就是以它命名的 |
| 4 | **STT** `transcriber` | 把这段音频变成文字。Whisper 在这一步 |
| 5 | **后处理** | 听模式：翻译成中文；说模式：去口水词、加标点 |
| 6 | **Sink（出口）** | 听模式：显示到字幕面板 + 存进会话文件；说模式：塞进你光标所在的地方 |

这条从入口到出口的固定路线，叫 **管线（pipeline）**。整条管线的形状加上"每个位置可以换成什么"，就是**架构**。

**Utter 架构的关键一招**：听和说两个模式，走的是**同一条管线**，只是每个位置换了零件（详见 [v3 设计 §4](plans/2026-08-09-v3-design.md)）。这就是"融合式平台"能成立、而不是把两个软件硬捆在一起的原因。

> 这个"一串处理环节顺序连接、每环只管自己那一小步"的形状，在软件里有个标准名字叫 **Pipes and Filters（管道与过滤器）**。知道名字的好处是：你可以直接去查它的经典讨论。

## 三、抽象接口与 provider：为什么换模型不用改程序

这是 v3 最重要的一个设计词，用翻译研究的话最好解释。

**接口（interface）** 就是一份**岗位说明书**：「给你一段音频，你还我一段文字。」说明书不规定你是谁、用什么方法。

**provider（提供方）** 就是**来应聘这个岗位的具体某一位**：MLX 版 Whisper 是一位，faster-whisper 是一位，云端的 Groq 也是一位。

只要都照说明书办事，系统就不用管换的是谁。**所以你同学的 Windows 机器换一个 provider 就能跑，而 Utter 的主体代码一行不改。**

> 这个"核心逻辑只认说明书、具体实现随便换"的架构模式，标准名字叫 **Ports and Adapters**（端口与适配器），也叫 **Hexagonal Architecture**（六边形架构）。你在 v3 设计里看到的 `SttProvider` / `LlmProvider`，就是两个 port；每个具体实现是一个 adapter。

## 四、数据怎么处理：三类数据，三种命运

"数据处理"在这个项目里不是一件事，是三件——**分开对待本身就是设计**。

**1. 音频 —— 最短命，永不落盘**

只在内存里活几秒钟，转成文字立刻丢弃。硬盘上不留任何录音。这既是省空间，更是隐私设计：**Utter 不产生录音文件，所以也不存在录音泄漏。**

**2. 文字 —— 会话期间在内存，定期存盘**

转录结果与译文/润色结果。存成 JSON 放在 `~/Utter/sessions/`，每 30 秒自动存一次，改动后 500 毫秒也存一次，暂停和结束时立即存。可导出 txt / markdown / srt（字幕格式）。

> **落盘 / 持久化（persistence）** = 写进硬盘文件，关掉程序也还在。v1 的一个真实毛病就是设置**没有**落盘——Settings 页有个 Save 按钮，但它只改了内存里的值，一重启全部还原。写在沙上。

**3. 配置与密钥 —— 长期存活，但分开放**

- 普通设置（选了哪个模型、存哪儿、VAD 灵敏度）→ `~/Utter/config.json`
- **API key → macOS Keychain（系统钥匙串），不进任何明文文件**

分开放是有教训的：这个生态里别的项目出现过 `.env` 明文密钥静置两个月的情况。密钥进系统级保管箱，是唯一正确的做法。

## 五、其余高频词速查

| 词 | 意思 | 在 Utter 里 |
|---|---|---|
| **API** | 程序对外开放的"服务窗口"，别的程序按规定格式来调用 | 调 OpenAI/DeepSeek 翻译就是在调它们的 API |
| **key（密钥）** | 你调用某个 API 的身份凭证，像借书证。**泄漏＝别人拿你的账户花钱** | 进 Keychain，绝不进代码或明文文件 |
| **BYOK** | Bring Your Own Key，自带密钥。软件不含任何 key，谁用谁自己填 | 分发给同学时你不替任何人付费，也不担风险 |
| **state（状态）** | 程序此刻"记着的事"：在不在录音、已有哪些条目、暂停了没 | 前端的 `store` 就是存放这些的地方 |
| **量化（quantization）** | 降低模型权重的数值精度（如 16 位→4 位）换取体积和速度 | 类比把无损录音压成 mp3：小很多，质量略降。档位表里的 `4bit` 版就是这个 |
| **CLI** | 命令行界面，纯文字、无图形 | P1 先只做 CLI，因为界面最费时间，先确认核心跑得通 |
| **TDD** | 测试驱动开发：先写"这个功能应该满足什么"的检验代码，再写实现 | 每步都有客观验收标准，不靠"看起来像对的"。v2 计划就是这么写的 |
| **Gatekeeper / 公证** | macOS 的安全检查：未签名的应用首次打开会被拦 | 走开源分发，README 里写清楚绕过方法即可 |

## 六、关于"现成的空骨架"

会看到两类东西，别混为一谈：

**脚手架 / 模板（boilerplate、scaffold）** —— 一份配置好的空项目，`create-tauri-app`、`create-react-app` 这类命令生成的就是。**你已经用过了**：这个项目当初就是 `create-tauri-app` 生成的，`tauri.conf.json` 里那个 `productName: "frontend"`、`identifier: "com.d.frontend"`，还有 Rust 代码里没删的 `greet` 命令，全是模板残留。

> **教训：模板的红利在第 0 天，成本在之后每一天。** 现在 Utter 已经有能跑的 v1 和清晰的模块划分，再套一个新模板等于扔掉能用的代码去换一套约定——不值。**P1 不引入任何新脚手架。**

**架构模式（architectural pattern）** —— 不是代码，是一种被反复验证的"形状"。上文提到的 Pipes and Filters 和 Ports and Adapters 就是。**这类东西值得学名字**，因为知道名字才查得到经典讨论。

**规则文件（convention files）** —— 让项目保持一致、也让 AI 协作者少犯错的那些约定。这一类对你最有用，Utter 该补的是：

| 文件 | 作用 |
|---|---|
| `CLAUDE.md`（项目根） | 告诉每个新会话：这个项目是什么、怎么跑、有哪些铁律。**没有它，每开一个新会话都要重新考古** |
| `README.md` | 给人看的：一句话定位 + 怎么装 + 怎么跑 |
| `ruff.toml` / `.editorconfig` | 代码风格自动统一，不靠人记 |

**真正值得"借"的其实是参考实现，不是模板。** 与 Utter 同类的开源项目——OpenTypeless（Tauri + BYOK 听写，几乎就是我们的 P2）、RealtimeSTT、whisper_streaming——读它们怎么解决具体问题，比套一个通用模板有用得多。你 4 月其实已经调研过这几个（记录还在 `.claude/settings.local.json` 的白名单里）。
